# StudyBuddy video workspace

English | [中文](README.zh.md)

The rightmost editor toolbar action exits the project after pending edits settle. Explicit exit stops the project's active work, releases its native Conversation view and returns to the project library without automatic reopening. Switching panels still retains the editor. Version-history UI, eager loading and history-specific subscriptions are removed; timeline undo/redo and project files are preserved.

This desktop plugin pairs the original OpenFilm Studio editor with the existing native Harness Conversation. Each admitted project retains its own Session and draft. Main owns account scope, project admission, the local process, private transport and image references. Selecting a clip, region or frame appends references to the current draft without submitting it.

The active project's native Conversation supplies the existing right-side file preview surface, so exported video links and attachment cards open under that project's Session without changing the ordinary chat selection. The visible editor main frame may enter HTML fullscreen; generated film subframes, hidden editors and revoked account generations cannot request it.

The editor runs in an isolated guest with a top-frame-only preload. Generated film pages have a separate origin and no native API. Main accepts frame images only from the current project's media endpoint, bounds and normalizes them to PNG, and discards a viewer capture if its project or playhead changes. Original timeline layout and operations remain in OpenFilm.

The video domain runs as a dedicated Harness profile with scoped tools. Existing native media catalogs and execution own models, credentials, request identity and billing. Provider and custom-service settings are removed. Models settings reads the selected account/project's native catalog; chat model selection stays in Conversation. The editor opens in a light StudyBuddy theme and keeps the original panel layout. Bundled editable examples work offline. There is no standalone agent daemon or bundled second Electron/Node runtime.

Native models without the word-timing capability required by video TTS/transcription receive no video selection authority. Their absence does not block unrelated supported models in the same native catalog. Failed catalog requests and invalid native identities still fail closed.

Native model menus retain the editor's rendered guest and project state. While a foreground menu is open, the guest stops accepting pointer and keyboard input. Modal dialogs still conceal the guest, and account revocation removes it.

This integration remains under development. Native path selection, project cancellation, timed transcription/translation, persistent TTS/SFX results and native Session ZIP exports have scoped test coverage. Production resources remain disabled pending current catalogue coverage and complete original-account workflow acceptance. Music generation and online stock sources are excluded by the user; local media import and editing remain. Source tests and recorded supplier replays do not establish real native gateway, wallet or full GUI acceptance.
